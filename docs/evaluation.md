# Evaluation methodology

## Splits

| Split | Seed | Used for |
| --- | --- | --- |
| Calibration | `20260904` | Threshold sweep only |
| Held-out | `20260905` | Every reported number |

Tuning on the data you report on is leakage. The splits are generated by the
same code with different seeds and never mixed.

## Reconciliation metrics

Scored against `ground_truth.csv`, which the generator emits alongside the data.

- **match rate** — claimed matches / rows. Alone it means nothing: a matcher
  that pairs everything scores 100%.
- **precision** — correct / claimed. The headline.
- **false matches** — reported even at zero, because it is the number a
  skeptical reviewer looks for first.
- **recall** — correct / rows that genuinely have a match.
- **correctly unmatched** — rows with no correct match that we did not claim.
  Leaving a non-settlement credit alone is a success, not a miss.
- **by difficulty class** — per-style breakdown, so one easy class cannot carry
  the aggregate.

## Triage metrics

Scored separately, because the failure costs differ by orders of magnitude. A
wrong match corrupts the ledger; a wrong label mis-sorts a queue a human reads
anyway. The report does not blend them.

## Threshold calibration

Sweep `0.30 → 0.99` in `0.01` steps. At each point:

```
expected_cost = false_accepts x 1200  +  false_rejects x 30    (INR)
```

Both constants are stated in `evaluation/calibrate.py` and are the model's only
assumptions. Ties break toward the stricter threshold: when two settings cost
the same, handing more work to a human is the safer place to be wrong.

**Degeneracy guard.** If every proposal is correct (or every one wrong), the
curve has no false-accept term, the optimum is trivially "accept everything",
and the resulting number is an artefact of the sample. The run detects this,
declines to calibrate, and says so.

## Baseline

Regenerate it, never quote it from memory:

```bash
python3 -m evaluation.baseline data
```

Rules-only, no triage, on the current held-out split: **81.5% match rate,
100% precision, 0 false positives** — identical to the full system, because the
triage tier does not match and is not supposed to. That equality *is* the
result: the model tier had to beat the rules at matching to earn a place there,
and it did not.

An earlier draft of this file quoted 86.9% and described it as the held-out
baseline. It was not — it came from the pre-stratification 61-row dataset, which
had four fewer foreign credits and so a mechanically higher match rate. The
argument was unaffected but the provenance was wrong, and a mislabelled metric
costs as much trust as an invented one. `evaluation/baseline.py` exists so the
number in this file is always the number the command prints.

## Throughput

```bash
python3 -m evaluation.bench
```

Reported as a **median over repeats on a scaled-up batch**, because the 65-row
demo reconciles in 1–2 ms and timing that swings more than 2x between
consecutive runs. Quoting a single figure from it is cherry-picking.

## What the held-out split does and does not prove

Both splits come from the same generator, and the difficulty mix is fixed by
construction — every seed produces the same class composition, so match rate is
81.5% on all of them. Varying the seed therefore tests robustness to **values**
(different UTRs, amounts, dates), not to **distribution shift**.

Precision holds at 100% with zero false positives across 100 unseen seeds, which
is real evidence. It is not evidence that the matcher survives narration formats
this generator never produces. A real bank statement would contain some.

## Reproducing

```bash
make seed && make calibrate && make demo
```

Deterministic: same seeds, same numbers, no network required.
